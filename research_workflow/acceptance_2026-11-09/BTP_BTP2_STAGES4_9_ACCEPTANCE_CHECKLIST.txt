## 4. Evidence and status rules for every stage

Statuses: `NOT STARTED`, `IN PROGRESS`, `BLOCKED`, `DELIVERED / NOT VERIFIED`, `VERIFIED WITH LIMITATIONS`, `COMPLETE`.

An unchecked box below is a requirement awaiting verification, not a claim that the work was never done. Mark it only after recording its evidence. Mark a requirement `N/A` only with a rationale and impact statement. Unresolved critical requirements prevent COMPLETE; optional exclusions with disclosed limits may permit completion of a reduced scope.

Maintain one acceptance register with these fields:

```text
requirement_id, stage, expected_output, actual_artifact_path,
artifact_sha256, check_method, executed_at_with_timezone, run_id,
expected_result, observed_result, verdict, severity,
limitations, corrective_action, evidence_path
```

Allowed verdicts: `PASS`, `FAIL`, `NOT RUN`, `BLOCKED`, `N/A WITH REASON`. Do not prepopulate successful results. Separate automated checks from manual scientific review. A placeholder table, empty output, or all-missing matrix is not a successful analytical deliverable.

For every output verify: it exists, opens, has the required schema, contains meaningful eligible data, agrees with its generating inputs, and is accurately represented in the report. File hashes establish identity, not factual truth.

## 11. Universal output cross-check procedure

For each stage, perform this sequence and save the evidence:

1. **Enumerate:** list required artifacts and map to actual files; do not require duplicate filenames if equivalent existing outputs satisfy the requirement.
2. **Inspect:** open outputs; check schema, keys, types, units, row counts, missingness, coverage and source/version identity.
3. **Recompute:** independently calculate critical quantities from upstream evidence or prediction ledgers, rather than copying a report or reusing the same helper blindly.
4. **Check boundaries:** inspect month-end, uncertain dates, missing periods, overlapping labels, earliest forecast origin, release-time edges and zero metric denominators.
5. **Reconcile:** compare tables, figures, narrative claims, run logs and acceptance-register entries; explain every mismatch.
6. **Repair:** fix the narrowest responsible step, regenerate affected downstream outputs, and rerun the checks invalidated by that change.
7. **Sign off:** assign a status with evidence, scope and residual limitations. Preserve failed checks and superseded run identities.

Never resolve a failed check merely by changing the expected result. If the requirement itself was wrong, record a dated design amendment and its implications.
